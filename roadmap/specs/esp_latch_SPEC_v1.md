# esp_latch スペックシート

旧作「EFI Mounter」「EFI Mounter Reloaded」（Python＋CustomTkinter）の作り直し。旧版の機能を引き継ぎ、Tauriで作り直す。

## 1. 目的と想定用途

- macOSに接続したストレージのESP（EFIシステムパーティション）を、GUIで簡単にマウント・取り外しできるようにする
- 主な用途はHackintoshの作業支援。OpenCoreやCloverのEFIフォルダを、内蔵ディスク・USBメモリ・ディスクイメージのESPの間で行き来しながら編集する場面で使う
- 個人用。利用者は作者本人と、READMEを読んで導入するHackintoshユーザーを想定する

## 2. 機能要件

デバイスの一覧と詳細
- 接続中の物理ディスクとディスクイメージを、サイドバーに一覧できる。APFSコンテナなどの合成ディスクはサイドバーに出さない（S01）
- 各デバイスを、ボリュームのラベル名（大）とベンダー名（小）で見分けられる。ラベルはESPを除く最初のボリューム（APFSは「/」にマウントされるボリューム、なければ最初のマウント中のボリューム）から取り、ほかにもあれば「ほかN個」と添える。ラベルがなければベンダー名を、ディスクイメージはイメージのファイル名を大きく出す（S01、S01j）
- 各デバイスの種別（内蔵・外付け・ディスクイメージ）、ESPの数、マウント中のESPの数を、サイドバーで確認できる（S01）
- 一覧を「全て／ESPあり／物理（ディスクイメージを除く）」で絞り込める。該当がなければ空の状態を出す（S01、S01d）
- 選んだデバイスの識別子・接続・パーティション方式・容量を確認できる。ディスクイメージは、イメージファイルのパスと、それを保存している物理ストレージ（`disk1s1` 上など）も確認できる（S01、S01b）
- パーティション配置を帯グラフで確認できる。小さいパーティションは最小幅で描く（S01）
- ESP以外のパーティションを表で確認できる。APFSパーティションの下には、APFSコンテナとボリュームを折りたたみの入れ子で表示できる（S01）
- デバイスの接続・取り外し・状態の変化を検知して、一覧を自動で更新できる（設定でオフにできる。更新ボタンでも更新できる）（S01、S02）
- 起動直後と更新中は、スケルトンを表示する（S01e）

ESPの操作
- ESPをマウントできる。マウントしたら、設定に従ってFinderで開く（S01a）
- マウント中のESPを取り外せる。Finderで開き直せる（S01a）
- デバイスごと取り出せる。取り出す前に確認ダイアログを出す（設定でオフにできる）（S01i）
- マウント中のESPについて、マウント先と、ESP内のブートローダー（OpenCore・Clover）とその版を確認できる（S01a）
- マウント中のESPについて、空き容量と、ゴミ箱（そのESPの`.Trashes`）が占めている量を確認できる。空きが15%を切ったら強調する（S01a、S01k）
- ESPのゴミ箱にファイルが残っていれば警告を出し、「ゴミ箱を空にする」「ゴミ箱を空にして取り外す」で容量を取り戻せる。空にしたら、解放した容量を通知で知らせる（S01k、S01l）。背景：FinderでESP上のファイルを「ゴミ箱に入れる」と、同じESPの`.Trashes/<UID>/`に移るだけで容量が戻らず、EFIの入れ替えを繰り返すと容量不足になる
- 設定で、ESPを取り外すときにゴミ箱を自動で空にできる（既定はオフ）（S02）
- OpenCoreで起動している場合、起動に使ったESPに「起動に使用」の印がつく（S01）

権限とエラー
- 権限が必要な操作を初めて行ったときに、macOSの管理者認証を1回だけ求め、以降はアプリを閉じるまで認証なしで操作できる。補助プロセスが動いている間は、ステータスバーに「管理者権限で実行中」と出す（S01f、S01a）
- 認証がキャンセルされたら通知で知らせ、再試行できる（S01g）
- マウントに失敗したら、`diskutil`のエラーと実行したコマンドを通知で確認できる（S01h）
- 直前に実行したコマンドを、ステータスバーで確認できる（設定でオフにできる）（S01）

設定と操作ログ
- 言語（システムに合わせる／日本語／英語／中国語）、外観（システムに合わせる／ライト／ダーク）、起動時の絞り込み、マウント後にFinderで開くか、自動更新、取り出し前の確認、取り外し時のゴミ箱の自動削除、コマンドの表示を設定できる（S02）
- アプリが実行したコマンドと結果を、操作ログで一覧できる。コピー・消去ができる（S03、S03a）

## 3. 非機能要件

- 対応OS：macOS 11以降を目安とし、Apple silicon・Intelの両方で動く（Universalビルド）。最低バージョンはTauriと依存クレートの要件で確定する（委任）
- 国際化の基盤を持つ。対応言語のモードはモード2（初版から日本語・英語・中国語簡体字`zh-Hans`）。原文は日本語
- 権限：アプリ本体は一般ユーザーの権限で動かす。root権限が要る操作だけを補助プロセスに任せる（5章）
- 補助プロセスの安全性：受け付ける操作を許可リスト（ESPのマウント・取り外し、デバイスの取り出し、マウントポイントの作成、ESPのゴミ箱の削除）に限る。引数はBSD名の形式（`disk[0-9]+s[0-9]+`）を検証する。ゴミ箱の削除は、BSD名から現在のマウント先を引き直し、そのパーティションがESPであることを確かめたうえで、マウント先直下の`.Trashes`だけを消す（パスを外から受け取らない）。通信路はアプリ本体だけが使えるようにし（ソケットのパーミッションと起動時のトークン）、本体が終了したら補助プロセスも終了する
- 互換性：macOS 15のベータで、`diskutil mount`でESPがマウントできなくなる事例が報告されている。失敗時は、`/Volumes/EFI`などのマウントポイントを作って`mount -t msdos`でマウントする方法に切り替える（その場合もコマンドをログに残す）
- 外部送信：なし。ネットワークに接続しない
- データの保存：設定だけをアプリの設定ファイルに保存する。操作ログはメモリだけに持ち、ファイルに保存しない
- READMEに書く注意事項：ESPの書き換えは起動不能の原因になりうること、署名・公証がないため初回起動時に警告が出ることとその開き方、管理者権限を使う理由と範囲、ESP上で「ゴミ箱に入れる」と容量が戻らないこと（「すぐに削除」⌥⌘⌫ かアプリのゴミ箱の掃除を使う）

## 5. アーキテクチャ概要

責務ごとに分け、上位は下位のインターフェースだけに依存させる（SOLID・疎結合）。

- **UI層（Svelte）**：画面（S01〜S03）と状態の表示だけを持つ。データはストア経由で受け取り、操作はコマンド呼び出しで依頼する
- **アプリ層（Rust・Tauriコマンド）**：ユースケース単位（デバイス一覧の取得、ESPのマウント、取り外し、取り出し）。操作ログへの記録はここで行う
- **ディスク情報アダプタ**：`diskutil`・`hdiutil`の出力を、デバイス・パーティション・APFSコンテナのドメインモデルに変換する。ラベル名の選び方もここに置く
- **デバイス監視**：DiskArbitrationのイベントを受けて、一覧の再取得を要求する（間引きを入れる）
- **特権操作のゲートウェイ**：補助プロセスの起動（初回の認証）、接続、要求の送受信、終了を担う。アプリ層は「特権操作のインターフェース」に依存し、実装を差し替えられるようにする（テスト用の偽実装を含む）
- **補助プロセス（Rust・別バイナリ）**：許可リストの操作だけを、引数を検証して実行する
- **起動情報・ブートローダー検出**：NVRAMの起動パスの読み取りと、マウント中のESP内のファイル（`EFI/OC/OpenCore.efi`、`EFI/CLOVER/`など）からの判定
- **ESPの容量**：マウント先の空き容量（statfs）と、`.Trashes`の合計サイズの取得
- **設定**：設定ファイルの読み書き（Tauriのstoreプラグインなど。委任）

採用：Carbon Design System v11（`@carbon/web-components` 2.x）。ライトはg10、ダークはg100を土台にする。

テーマの上書き方針：`esp_latch_tokens.css`の`--cds-*`の値でCarbonのテーマを上書きする。Carbonにない項目（ロケール別の書体、角丸、マウント状態の色、帯グラフの色）は`--esp-*`で持つ。角丸は、Carbonの部品（ボタンなど）に最小限だけ当てる。

画面ID一覧：

| 画面ID | 画面名 | 状態 |
|---|---|---|
| S01 | メインウィンドウ | S01a マウント直後／S01b ディスクイメージ／S01c ESPなし／S01d 絞り込み結果が空／S01e 読み込み中／S01f 認証待ち／S01g 認証のキャンセル／S01h マウントの失敗／S01i 取り出しの確認／S01j 多数・長い名前／S01k ゴミ箱に古いファイルが残っている／S01l ゴミ箱を空にした／S01m 部品の状態 |
| S02 | 設定（別ウィンドウ） | — |
| S03 | 操作ログ（別ウィンドウ） | S03a 空 |

原則：

- アクセシビリティ：Carbonの部品のキーボード操作とフォーカス表示に従う。状態は色だけでなく文字（「マウント中」など）でも示す。帯グラフの各区画には、識別子・名前・容量のツールチップを付ける
- ウィンドウの基準幅：メインウィンドウは1100×720px（モックの幅）。最小幅はサイドバー＋詳細が崩れない範囲で決める（委任）
- 識別子・容量・マウント先・コマンドは等幅書体で表示する

コンポーネント方針：

- そのまま使う：ボタン（primary・secondary・tertiary・ghost）、コンテンツスイッチャー（絞り込み）、タグ、トグル、ドロップダウン、データテーブル、通知（トースト）、モーダル、スケルトン、ローディング
- 組み合わせて作る：デバイスの一覧項目（構造化リスト＋タグ＋小さな帯）、ESPのタイル（タイル＋タグ＋ボタン）、入れ子のパーティション表（データテーブルの展開行）
- 独自に作る（Carbonのトークンと作法に沿う）：パーティションの帯グラフ、ESPの容量バー、ステータスバー、macOSのタイトルバー周り

アイコンの展開先：macOSのアプリアイコン（`.icns`）、Liquid Glass用の`.icon`（作る）。`.icon`は`brand.md`の方針でユーザーがIcon Composerで作る。tauri-bundler 2.9系には`.icon`をバンドルに組み込む処理があるので、それを使う。不安定なら`.icns`へフォールバックする。

確定事項（変更禁止）：Carbon Design System v11（`@carbon/web-components` 2.x）、`tokens.css`の値、画面構成（画面ID・各画面の要素と配置・画面遷移・描いた状態・どこに何の文言があるか）、マスターSVGとそのレイヤー構成、アイコンの余白ルール。

委任事項：モックの実装方式（コンポーネント分割、ピクセル単位の再現の程度）、トークンをCarbonのテーマへ対応づける実装、アイコンの各形式への展開（前景グループのレイヤーごとのSVGの書き出しと、`.icon`のビルドへの組み込み）、コンポーネントへのトークン適用、縮小表示の確認、文言の言い回しと辞書のキー設計。

ユーザーが作るもの：`AppIcon.icon`（Icon Composer）。

## 7. 配布・公開方法

- GitHub Releasesで配布する。ビルドはtauri-actionで、macOSの`universal-apple-darwin`（Apple silicon＋Intel）を作る。Windows版は作らない
- 成果物は`.dmg`
- バージョニングはSemVer、初回は`0.1.0`
- コード署名・公証は行わない。READMEに、初回起動時の警告と開き方（「プライバシーとセキュリティ」から許可する方法など）を書く

## 8. スコープ外

- Windows・Linux版
- メニューバーへの常駐
- 操作ログのファイル保存
- ESPの中身の編集（config.plistの編集、EFIフォルダのコピーなど。Finderや既存のツールに任せる）。例外は、ESPのゴミ箱（`.Trashes`）の削除だけ
- ESP以外のパーティションのマウント・取り外し（デバイスごとの取り出しは除く）
- パーティションの作成・削除・フォーマット（ESPの再フォーマットを含む。容量不足はゴミ箱の掃除で解消する）
- 自動アップデート

## 9. 未決定項目

プロジェクト・スタートで、次のとおり決定した（いずれも初版の範囲）。

- **Clover起動時の「起動に使用」の判定**：(b) OpenCoreだけ対応し、Clover起動時は印を出さない
- **ブートローダーの版の取り方**：(a) `OpenCore.efi`・`CLOVERX64.efi`などのバイナリに埋め込まれた版の文字列を読む。読めなければ名前（「OpenCore」「Clover」）だけを出す
- **macOSの付随ファイルの掃除**：(b) `.Trashes`だけを消す
- **補助プロセスの通信方式**：(a) Unixドメインソケット。`do shell script`はコマンドの終了まで戻らず、標準入出力のパイプを保てないため。トークンは、本体が作る一時ディレクトリ（0700）のファイル（0600）で渡し、補助プロセスが読んだら消す。ソケットは利用者のUIDに0600で渡す
- **操作ログの粒度**（追加の決定）：一覧の取得のための読み取りコマンド（`diskutil list`・`info`・`apfs list`、`hdiutil info`）は、更新1回につき`diskutil list -plist`の1行にまとめる。読み取りに失敗したときだけ、失敗したコマンドを個別の行で残す。操作（マウント・取り外し・取り出し・ゴミ箱の削除・Finderで開く・補助プロセスの起動）のコマンドは、すべて記録する

残っている項目：

- **トークンのコントラスト**：ライトの`--esp-state-mounted`（「マウント中」タグの文字。背景`--esp-state-mounted-bg`に対して3.55）と、ダークの`--cds-button-primary`・`-hover`（白い文字に対して4.29・3.66）が、WCAG AAの4.5に届かない。claude.aiで調整し、改訂版プランアセットを持ち込む（帯グラフの「その他」・HFS+の区画の3:1未満は、ラベルとツールチップで補うためそのままとする）
